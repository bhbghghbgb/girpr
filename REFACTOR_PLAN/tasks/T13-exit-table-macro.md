# T13 — Exit-table mechanism macro

## Goal / pointers
- `docs/08-shared-crate-refactor-research.md` §F22 (lines 316–321) — the
  exit-table *mechanism* is duplicated; the tables are not.
- Assumptions to validate: §A9 (78–81), §A2 (21–27), §A1 (13–19).
- Related: T12 (`girpr-cli` is a possible home for the macro).

## Scope
- Candidate home: `girpr-cli` (T12) or a tiny `girpr-exit` leaf for the macro
  only.
- Report names: `src/config.rs` (`define_run_exits!`, generating enum + `ALL` +
  code mapping + compile-time pin), `tools/capture/src/exit/mod.rs`
  (hand-written equivalent with `slug`, `describe`, `artifact_is_untrustworthy`).
  Locate before editing.

## Implementation plan
1. Validate §F22 and §A9: the generated *mechanism* is common; values, meanings,
   `slug`, `describe` and `artifact_is_untrustworthy` are capture's own contract.
2. Provide a parameterised table macro that emits the enum + `ALL` + code mapping
   + pin from a supplied list, while letting each tool supply its own values and
   helper methods.
3. Migrate girpr's macro and capture's hand-written table to the shared macro,
   keeping every code, slug and description byte-identical (§A3).
4. Keep the mapping from usage errors to exit codes in each tool (T12); do not
   couple the tables.

## Constraints / validation
- Exit codes and meanings must not change (§A9, §N3), including capture's 1/2
  overlap with girpr.
- No program logic in the leaf (§A1, §A2).
- A new gircap leaf dep requires §A2 doc tables to be updated.

## Done when
Both exit tables are generated by the shared macro, all codes/strings are
unchanged, and exit-code tests pass in both tools.
