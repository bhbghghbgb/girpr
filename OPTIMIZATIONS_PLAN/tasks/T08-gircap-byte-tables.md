## Goal

`World::all_shapes()` zstd-encodes ~25 blobs and computes ~60 MD5s on every
capture, but most tests assert metadata, not bytes. Cache the byte tables so
they are computed once per process, and shrink the largest chunk (32 KB
`old.blk`) where its bytes are not asserted. This targets gircap's CPU/syscall
cost, which the report says is the dominant remaining cost for this crate after
capture consolidation.

## Implementation plan

Code anchors from the report (validate before editing):

* `tools/capture/tests/common/mod.rs:308–424` — `World::all_shapes()`; the 32 KB
  `old.blk` around `:329`.
* Look for the helper(s) that zstd-encode blobs and compute MD5s; decide what can
  be memoized safely (tables are immutable per process).

Possible commits:

1. Wrap the generated byte tables in a per-process `OnceLock` (or equivalent)
   so encoding/hashing happens once, not per `all_shapes()` call. Keep the
   tables immutable; confirm no test mutates them.
2. Shrink the oversized `old.blk` chunk where no test asserts its byte content
   or resulting digest; keep enough size to exercise any size-dependent
   behavior the tests rely on.

## Acceptance criteria

* Encoding/MD5 work for the standard shape set happens once per process instead
  of once per capture.
* All gircap tests still pass; the shared tables are not mutated by any test.
* The largest chunk is materially smaller where bytes are not asserted.

## Guardrails

* Validate against current code first; if the tables/chunk structure differs,
  stop and mark `skipped` with a note.
* Note the report's caveat (§5): a per-process `OnceLock` only helps multi-capture
  tests within one process; it does not share across nextest processes — T06
  handles cross-process reuse. Do not claim cross-process benefit here.
* Test-only change; do not alter zstd/MD5 product behavior. Run the gircap suites
  to verify; report follow-up ideas without implementing them.
